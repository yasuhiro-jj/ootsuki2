# 要件

対象は `apps/gps-sales`。既存の ootsuki2 チャットボット、`frontend/`、`ai-maneger/`、`admin-portal/`、`platform_custom/` は変更しない。

## プロダクト

複数企業向けの GPS 営業訪問管理。初期範囲は企業・所属・権限と顧客 CRUD。訪問の位置、写真、地図、報告書は画面の枠だけ。課金、AI 日報、利用規約の文面は作らない。

企業のデータは分離する。ログインユーザーの所属を確認し、その `organization_id` だけで読み書きする。URL の slug やリクエスト中の ID だけでは許可しない。

## 画面

- `/login`、`/signup`、`/select-organization`
- `/app/[orgSlug]/dashboard`
- `/app/[orgSlug]/customers`（作成、一覧、名前の更新、削除）
- `/app/[orgSlug]/visits`、`/visits/new`、`/visits/[id]`、`/map`、`/reports` は Phase 2 の枠
- `/app/[orgSlug]/settings/members`、`/settings/organization`
- `/admin` は運営向けの枠。企業データは読まない

## Phase 1 の受入

- 未ログインの API は 401
- 未所属は 404。停止中の所属は 403、招待未承諾は 403、停止・閉鎖中の企業は 403
- 他社の顧客は一覧に出ず、取得も更新もできない
- 最後の有効なオーナーは削除、降格、停止できない
- スタッフはメンバー招待・変更・削除ができない

## この段階で決めたこと

- 顧客の作成・更新・削除は、有効な所属なら役割を問わない。仕様は訪問の編集とメンバー管理だけ役割を分けている
- 顧客に削除日の列はない。訪問が無い顧客は物理削除し、訪問があると 409
- 招待は、既に Better Auth にいるユーザーのメールアドレスだけ。メール送信と期限は作らない
- メールアドレス確認は無効。送信用の基盤は後続
- 未所属と存在しない企業はどちらも 404。権限不足・停止・招待中は 403
- 顧客作成は任意の UUID を冪等キーにする。同じ企業に同じ ID があれば既存の行を返す。他社の ID は 409 で、中身は返さない
